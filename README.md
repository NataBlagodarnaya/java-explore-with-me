# java-explore-with-me
Афиша для организации мероприятий: пользователи публикуют события, находят интересные и подают заявки на участие. Проект состоит из двух сервисов: основного и сервиса статистики просмотров.

## Архитектура

- **main-service** (порт 8080): вся основная логика. Пользователи, категории, события, заявки на участие, подборки событий. База данных `ewm-main`.
- **stats-service** (порт 9090): сохраняет обращения к эндпоинтам и отдаёт статистику просмотров. База данных `ewm-stats`. Состоит из трёх модулей: `stats-dto`, `stats-client` и `stats-server`.

Основной сервис отправляет в статистику информацию о каждом просмотре списка событий и страницы события, а при выдаче событий запрашивает количество просмотров (по уникальным IP). Если статистика недоступна, события всё равно открываются, а просмотры показываются нулевыми.

## Технологии

Java 21, Spring Boot 3.3, Spring Data JPA, PostgreSQL 16, Maven (многомодульный проект), Docker и Docker Compose, JUnit 5, Mockito, H2 (для тестов), Lombok, Checkstyle.

## Структура проекта

```

├── stats-service
│   ├── stats-client      клиент сервиса статистики
```

## Запуск

Нужны Java 21, Maven и Docker.

```
mvn clean package
docker compose up -d --build
```

Остановить сервисы:

```
docker compose down
```

Порты:

| Сервис | Порт |
|---|---|
| Основной сервис | 8080 |
| Сервис статистики | 9090 |
| PostgreSQL основного сервиса (с хоста) | 6544 |
| PostgreSQL статистики (с хоста) | 6543 |

Адрес сервиса статистики основной сервис берёт из переменной окружения `STATS_SERVER_URL` (в Docker это `http://stats-server:9090`).

## API основного сервиса

- **Публичный:** поиск и просмотр опубликованных событий (`/events`), категории (`/categories`), подборки (`/compilations`).
- **Закрытый (для пользователя):** события пользователя (`/users/{userId}/events`), заявки на участие в чужих событиях (`/users/{userId}/requests`), управление заявками на своё событие (`/users/{userId}/events/{eventId}/requests`).
- **Административный:** пользователи (`/admin/users`), категории (`/admin/categories`), события (`/admin/events`), подборки (`/admin/compilations`).

Полное описание эндпоинтов лежит в файле `ewm-main-service-spec.json`.

## API сервиса статистики

- `POST /hit`: сохранить информацию о запросе к эндпоинту.
- `GET /stats`: получить статистику за период (параметры `start`, `end`, `uris`, `unique`).

Описание лежит в файле `ewm-stats-service-spec.json`.

## Основные правила

**События.** Новое событие получает состояние `PENDING`. Администратор публикует его (`PUBLISHED`) или отклоняет (`CANCELED`). Дата события должна быть не раньше чем через 2 часа от момента создания или изменения, а для публикации не раньше чем через час. Автор может менять только неопубликованные и отменённые события. Публичный поиск показывает только опубликованные события.

**Заявки на участие.** Нельзя подать повторную заявку, нельзя участвовать в своём или неопубликованном событии. Если у события включена модерация и есть лимит участников, заявка ждёт решения автора (`PENDING`), иначе подтверждается сразу. Лимит `0` означает отсутствие ограничения. Когда лимит набран, остальные заявки в ожидании отклоняются автоматически.

**Подборки.** Администратор создаёт подборки событий и может закреплять их (`pinned`).

## Тесты

- **Unit-тесты** сервисов (Mockito), **REST-тесты** контроллеров (`@WebMvcTest`), **JSON-тесты** DTO.
- **Интеграционные тесты** запускают приложение целиком на базе H2, клиент статистики в них подменён.
- **Postman:** коллекция `ewm-full-tests.json` покрывает все эндпоинты обоих сервисов. Импортируйте её в Postman (Import) и запустите через Run collection при поднятых сервисах.

Запуск всех тестов, проверки стиля (Checkstyle), поиска ошибок (SpotBugs) и проверки покрытия (JaCoCo):

```
mvn clean verify -P check,coverage
```
